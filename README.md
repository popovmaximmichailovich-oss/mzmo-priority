# Приоритизация объектов здравоохранения МЗ МО

Статическое веб-приложение для GitHub Pages. Уровень 2: база объектов обновляется вручную через файл `data/objects.json`, расчёты выполняются в браузере.

## Состав

- `index.html` — главный экран приложения.
- `styles/main.css` — адаптивный интерфейс под рабочие мониторы.
- `src/calculator.js` — расчёт F1–F6, рейтинга, зоны, достоверности данных и рекомендаций.
- `src/dashboard.js` — дашборды и диаграммы.
- `src/app.js` — форма, таблица, фильтры, сохранение, импорт/экспорт.
- `data/objects.json` — база объектов, 2208 строк.
- `data/fields.json` — все 78 показателей исходной модели.
- `data/dictionaries.json` — выпадающие списки.
- `data/config.json` — веса, пороги, обязательные поля и карта колонок.

## Как запустить локально

Из-за загрузки JSON через `fetch` открывать `index.html` двойным кликом может быть нельзя в части браузеров. Запускайте локальный сервер:

```bash
python -m http.server 8000
```

Затем откройте в браузере:

```text
http://localhost:8000
```

## Как обновлять базу вручную

1. Открыть приложение.
2. Отредактировать объекты в карточке или импортировать обновлённый JSON.
3. Нажать `Экспорт JSON`.
4. В репозитории заменить файл `data/objects.json` экспортированным файлом.
5. Сделать commit в ветку `main`.
6. GitHub Pages опубликует обновлённую версию.

## Как включить GitHub Pages

В репозитории GitHub: `Settings` → `Pages` → `Build and deployment` → `Source: GitHub Actions`.

В проект уже добавлен workflow `.github/workflows/pages.yml`.

## Принцип расчёта

Итоговый рейтинг считается как нормированная сумма F1–F6 по весам из `data/config.json`:

- F1 — технический риск.
- F2 — территориальная безальтернативность.
- F3 — программный / управленческий блок.
- F4 — надзорный и юридический риск.
- F5 — системная роль / уникальность.
- F6 — медицинская нагрузка.

Если выявлен критический надзорный риск, риск остановки деятельности или судебный/исполнительный риск, объект автоматически не опускается ниже зоны II.

## Важное ограничение

Приложение не выдумывает отсутствующие данные. Пустые экспертные показатели учитываются как `Нет данных` и снижают достоверность расчёта. Центральная база меняется только после ручной замены `data/objects.json` в репозитории.

## v2.1: массовое дозаполнение

Добавлен блок «Массовое дозаполнение»:

1. Сначала отфильтруйте таблицу: поиск, зона, тип, статус данных.
2. Выберите показатель для заполнения.
3. Выберите значение из выпадающего списка или введите текст/число.
4. Нажмите «Проверить охват», чтобы увидеть количество объектов.
5. Нажмите «Применить к фильтру».
6. Проверьте дашборд и таблицу.
7. Нажмите «Экспорт JSON» и замените `data/objects.json` в GitHub.

Это основной рабочий сценарий для доведения большого реестра до качества, пригодного для регулярной приоритизации.
